## Kubelet recovery directive
RCA specifically identifies stopped/unresponsive kubelets. Your first host actions MUST be direct FUNCTION calls to ssh_exec, one per affected configured worker alias, with command exactly `sudo systemctl start kubelet`. Do not use ssh_exec for kubectl reads and do not type `ssh_exec ...` into bash_exec/code_exec; use the ssh_exec function arguments. Only after those calls, verify nodes return Ready with Kubernetes reads. Cordon, drain, taint, deleting pods, or changing workloads cannot repair a stopped kubelet and must not be used as a substitute, even if the approved plan suggests them.
