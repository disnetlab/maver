Use `exec_kubectl_cmd_safely` for every cluster operation — it runs read and mutating kubectl verbs, and `rollback_command` undoes the last mutation. `code_exec` (Python) and `bash_exec` run in a sandbox with NO cluster credentials, so kubectl inside them fails — use them only to filter, parse, or compute over output you already captured. When output may be long or reused, pass `save_as="name.json"` to `exec_kubectl_cmd_safely` (written to `tool_outputs/` in your sandbox dir) and read it back with a relative path. Verify changes with short reads; one bounded `kubectl rollout status ... --timeout=60s` is acceptable in this mode. Never use interactive or attaching flags (`-i`, `-t`, `-it`).
