- `bash_exec` / `code_exec`: run normal `kubectl` commands directly. They resolve to a stage-aware shim that routes through the SREGym MCP filtering proxy. Execution may run read and mutating kubectl verbs, but must still follow the approved plan, check-and-set preconditions, and verify each change. `exec_kubectl_cmd_safely` and rollback tools are not available in this mode. Do not use `kubectl wait` or `kubectl rollout status` in proxy_exec; verify with short `kubectl get ... -o json/jsonpath` reads of the patched field, Ready replicas, pods, events, logs, endpoints, or SLI.
